# 决策引擎设计说明

驱动 `driver/driver.py` 只做一件事：**收到一个游戏状态，回一条指令**。游戏每次执行完指令都会重发状态，所以引擎不需要做多步规划，只需保证"每一步都选当前最优"。

---

## 1. 通信协议

| 方向 | 内容 |
|---|---|
| 游戏 → 驱动（stdin）| 一行一个 JSON，含 `game_state`（牌组/遗物/金币/HP/楼层/幕/地图）、`combat_state`（手牌/怪物意图/能量/格挡）、`screen_state`（当前界面详情）、`available_commands` |
| 驱动 → 游戏（stdout）| 一行一条指令：`PLAY <手牌序号> [目标序号]`、`END`、`CHOOSE <序号>`、`POTION use <槽位> [目标]`、`PROCEED`、`RETURN`、`START <角色>`、`STATE` |

**关键坑**：Mod 侧用平台默认编码（简体中文 Windows = GBK）写 JSON，驱动必须按 `utf-8 → gbk` 顺序尝试解码，否则所有中文（事件文本、卡名）会损坏。

---

## 2. 状态数据结构要点

驱动依赖的字段（实测确认）：

```
game_state:
  class / act / floor / current_hp / max_hp / gold / act_boss
  deck[]        {id, name, type, cost, upgrades, is_playable}
  relics[]      {id, name}
  potions[]     {id, name, can_use}
  map[]         {symbol(M/?/R/$/E/T/B), x, y, children[{x,y}]}
  screen_type   NONE / MAP / CARD_REWARD / COMBAT_REWARD / SHOP_SCREEN / REST / EVENT / GRID / HAND_SELECT / GAME_OVER
  screen_state  随界面不同：cards[]（奖励/商店）、relics[]、choices[]、next_nodes[] …
  choice_list   当前可选列表（卡牌奖励为小写卡名；篝火为 rest/smith；奖励屏为 gold/card/relic/potion）

combat_state:
  hand[]        {id, type, cost, is_playable, upgrades}
  monsters[]    {id, name, current_hp, max_hp, block, intent, move_adjusted_damage, move_hits, powers[]}
  player        {current_hp, max_hp, block, energy, powers[]}
```

怪物列表**包含尸体**（`current_hp=0` / `is_gone` / `half_dead`），指定攻击目标时必须使用原始索引。

## 3. 决策分层（战斗）

按优先级从上到下，命中即返回：

1. **药水斩杀**：火药水/爆炸药水可直接击杀残血怪时使用
2. **攻击斩杀**：所有攻击牌总伤害 ≥ 目标剩余血量+格挡 → 打最高伤害的攻击
3. **统一药水估值**：对每瓶持有的药水计算"等效价值分"（见第 6 节），超过门槛（普通战 5 分 / 精英 4 分 / Boss 3 分 / 残血 0 分）就使用最优的那瓶
4. **易伤覆盖**（Boss/精英战）：目标无易伤且有高伤害攻击牌时优先上易伤（伤害 ×1.5）
5. **虚弱**：来袭伤害 ≥ 10 且目标无虚弱时，优先上虚弱或使用虚弱药水
6. **绝望防御**：预计伤害足以致死（`hp ≤ 来袭伤害 + 2`）时，强制打最大格挡
7. **格挡**：按房间危险度设置阈值（Boss 3 / 精英或半血以下 4 / 普通 6），来袭伤害（扣除已有格挡）超过阈值时打格挡牌
8. **铺能力牌**：安全回合优先打出 buff 类能力牌
9. **铺毒**：长线战斗（怪物血量高）或毒流卡组时优先叠毒
10. **最大攻击**：默认动作；优先攻击血量+格挡 ≤ 3×本次伤害的目标
11. **剩余格挡**：能量有余时补格挡

**怪物特化**：
- `Lagavulin`（拉格瓦林）：醒来后每回合 18-20 伤害 → 格挡阈值降为 3
- `GremlinNob`（地精大汉）：激怒（每张技能 +2 力量）但**不能因此不格挡**——不格挡的 20 伤回合会直接致命
- `Slime Boss`（史莱姆王）：分裂阶段优先群伤

**攻击力估算**：卡牌伤害 + 力量加成，虚弱 ×0.75；格挡估算同理（含敏捷加成、脆弱 ×0.75）。`estimated_block` 的减益处理很重要——被拉格瓦林"吸魂"后防御牌只有 4 点格挡，早期实现因"格挡 ≥5 才考虑打"的条件直接放弃了防御，导致被活活打死。

## 4. 选卡与构筑倾向

每张候选卡打分：

```
分数 = 卡牌强度表(基础分) + 构筑倾向加成 + 遗物联动 + Boss 针对性加成
```

- **强度表**：内置 80+ 张卡的分值（1.0 普通 ~ 3.5 顶级），未收录卡默认 1.0
- **构筑倾向**：识别力量流（加力量卡 ↔ 多段攻击）、格挡流、毒流、幻影刃流、消耗流，同类卡达到阈值后核心件加分
- **遗物联动**：手里剑/苦无 → 幻影刃系；蛇眼 → 毒卡；笔尖 → 多段攻击
- **Boss 针对性**：本幕 Boss 从第 1 层即可知（`act_boss` 字段）——史莱姆王偏群伤、六火亡魂偏格挡成长、守卫者偏格挡+爆发
- **选卡纪律**：卡组越大越挑（阈值随卡组规模上升），避免"均衡垃圾堆"——实测伤害不足是打不过 Boss 的主因（每回合 11 伤 vs 需要的 20+）
- **跳过**：低于阈值宁可污染也不拿（`RETURN` 跳过）

## 5. 路线与资源

**路线规划**：用完整地图数据做 6 层 beam 搜索（越远权重 ×0.85 衰减），对整条路径打分：

| 节点 | 权重 |
|---|---|
| 篝火 R | 血量越低越高（<45% 3.5 分）；Boss 前楼层加码 |
| 宝箱 T | 2.0 |
| 商店 $ | 金币 ≥150 → 1.6；血量 <35% → -2（钱救不了死人）|
| 怪物 M | 卡组 <18 张 → 1.4；血量 <25% → -3（濒死避战）|
| 问号 ? | 血量低时 +1（事件可能回血）|
| 精英 E | 仅当血量 ≥85%（第一幕）且卡组强度 ≥8 分才考虑；否则重罚 |

**篝火**：休息价值 = min(缺口, 30% 上限) × 系数（溢出治疗打折）；锻造价值 = 基础分 + 未升级核心卡数量加权；血量 ≤45% 强制休息，Boss 前 3 层且血量 <85% 休息权重 +0.2。

**商店**：删卡（按实际价格 + 保留 90 金）> 遗物（保留 80 金）> 卡牌（第一幕 ≥2.0 分 / 后续 ≥2.5 分）> 药水（有空位）。删卡优先级最高是打击/诅咒。

## 6. 药水估值表

29 种药水统一折算为"等效价值分"，每回合挑最高分且超过门槛的一瓶：

| 药水类型 | 估值方式 |
|---|---|
| 伤害类（火焰/爆炸）| 斩杀收益 = 目标血量 + 威胁伤害×1.5；否则按削血计分 |
| 力量/敏捷（含类固醇）| 2.2 × 本回合能量内实际能打出的攻击/格挡牌数量（旋风斩额外 +1）|
| 能量 | 手牌总费用超出当前能量的幅度 |
| 格挡/幽灵瓶 | 与残余伤害挂钩（幽灵瓶按多段攻击的段数折抵）|
| 治疗类（血瓶/再生）| 按缺失血量与预估战斗回合数折算；近死时门槛降为 0 |
| 持续类（祭司/金属化/镀铁）| 单位收益 × 预估剩余回合数 |
| 抽牌/随机卡/复制/锻造 | 手牌资源枯竭时或配合大攻击时 |
| 烟雾弹 | 血量 <35% 且非 Boss 战 = 30 分保命 |

**节奏规则**：简单小怪战（单怪 ≤40 血）门槛提高到 8 分（不浪费）；进 Boss 前 3 层普通战门槛 +2（攒资源）；Boss 战与残血时门槛降到 3/0。

## 7. 多职业支持

驱动为四个职业共用一套决策骨架，职业差异通过"数据表 + 少量职业分支"实现，`character.txt` 选择职业（`IRONCLAD` / `THE_SILENT` / `DEFECT` / `WATCHER` / `RANDOM` / `ROTATE`）。

| 职业 | 专属逻辑 |
|---|---|
| **铁甲战士** | 力量流（燃心/观察弱点/恶魔形态 × 多段攻击）、格挡流（金属化/壁垒/全身撞击）；消耗流协同（腐化/无惧疼痛/黑暗拥抱）|
| **静默猎手** | 毒流（催化剂/尸爆/致命毒）、幻影刃流、敏捷流；带目标技能自动附带目标索引 |
| **机械师** | 充能球体系：冰球被动格挡计入"残余伤害"（避免过度格挡）、`Zap`/`Dualcast` 在安全回合主动铺设（否则每回合浪费能量）；选卡偏向伤害牌，防止"防御堆满打不死 Boss" |
| **观战者** | 姿态体系：Mod **不上报姿态**，驱动用影子追踪器维护（记录自己打出的起焰/暴怒/平静/封印破除）；愤怒态下"受到伤害 ×2"参与格挡决策、攻击估值 ×2；危险回合优先退出姿态；血量 <55% 且来袭 ≥12 时不主动进愤怒（除非当回合能斩杀）|

共同机制：
- `CARD_DB` / `CARD_TIER`：各职业卡牌数值与抓取优先级（未收录的卡走通用回退值）
- `UPGRADE_PRIORITY_BY_CLASS`：按职业的锻造顺序（篝火界面按 `game_state.class` 选择）
- `synergy_bonus()`：按流派池加成（力量/毒/幻影刃/消耗/冰球专精/姿态循环）
- 未解锁职业：`START` 连续失败 3 次判定为锁定，随机/轮换时跳过，每 8 局重试

## 8. 稳定性设计

- **崩溃保护**：决策函数异常不会杀死驱动，会记录 `DECISION CRASH` 并跳过该状态
- **震荡保护**：检测 A↔B 界面来回切换（历史窗口比对），自动刹车 3 秒
- **防死循环**：同一决策重复 200 次自动休眠
- **速率限制**：指令间固定 0.1 秒间隔，避免高频指令导致画面频闪
- **奖励屏状态机**：金币/遗物/药水按行获取，卡牌只开一次，避免"打开卡牌→跳过→再打开"的死循环
- **界面类型优先于房间类型**：GRID（删卡/转化）、战斗奖励屏等可能在 `room_type` 仍是商店/宝箱时出现，路由必须先按 `screen_type` 分发，最后才按房间兜底
- **带目标技能统一出口**：`play_card()` 依据卡牌的 `has_target` 决定是否附目标索引，避免"Selected card requires an enemy target"死循环
- **影子姿态**：跨状态维护观战者姿态，非观战者强制清空，避免跨职业/跨会话污染
